Benchmark summary

We deployed Gemma 4 12B with Ray Serve and vLLM on Amazon EKS and evaluated six deployment options across NVIDIA L40S and H100 GPUs. The comparison includes the BF16 baseline, FP8 KV cache with n-gram speculative decoding, the W4A16 QAT model, and H100 tensor parallelism across four GPUs.

Using the six supplied prompts, we completed 48 primary tests covering cold- and warm-prefix latency, prefill, fixed-length decode, and concurrent request throughput from 1 to 16 requests. All measured requests completed without transport errors.

This report compares user-visible latency, token throughput, GPU allocation, and estimated compute cost efficiency. Its purpose is to help select the best deployment for a latency SLA, expected concurrency, model-quality requirements, and available GPU budget.

How to read the metrics

TTFT — Time to First Token: the delay from submitting a request until the first response token arrives. It captures prompt processing and queueing, and is the most noticeable latency for interactive users. Lower is better.

E2E — End-to-End latency: the total time from submitting the request until the complete response is returned. Lower is better.

Prefill throughput: how quickly the model reads and processes input prompt tokens before generating the answer. It matters most for long prompts, documents, and large shared context. Higher is better.

Decode throughput: how quickly one active request generates new output tokens after the first token. It influences how fast the answer streams to the user. Higher is better.

C16 — Concurrency 16: sixteen requests were sent at the same time. C16 output is their combined output-token throughput, not the speed of one request. Higher values mean the deployment can serve more simultaneous work.

C16 tok/s per allocated $/hr: C16 output throughput divided by the hourly compute cost allocated to that deployment. It is a relative cost-efficiency score; higher is better. P5 allocation is valid only when its remaining GPUs are productively used.

Performance versus cost

  • H100 TP=4: best technical result. It uses half of a p5.48xlarge; the other four H100s can host another isolated model deployment, improving instance utilization.
  • H100 TP=1 BASE: better balance when one H100 meets the SLA.
  • L40S QAT: best tested L40S performance and the leading cost-oriented candidate.
  • Allocated cost: P5 cost is divided by active GPU share only when the remaining GPUs serve other workloads. Replace the reference rates with the customer's contracted rates for the final business case.

Optimization takeaways

  • Prefix caching: recommended for repeated long prefixes; warm TTFT was roughly 0.1 seconds.
  • N-gram speculation: improved low-concurrency decode, but did not beat H100 BASE at concurrency 4–16.
  • FP8 KV: useful for KV capacity, but validate numerical quality against customer thresholds.
  • TP=4: valuable when latency and capacity justify four GPUs; scaling is not free or perfectly linear.

Recommendation by instance choice

The deployment pattern changes depending on whether the customer prioritizes absolute performance or GPU economics.

If choosing P5

Use H100 TP=4, then utilize the other four GPUs

Run one four-GPU TP=4 replica for the latency-sensitive model. Use GPUs 4–7 for a second isolated TP=4 replica or another model. Two TP=4 workers fit within the p5.48xlarge CPU and memory envelope, but benchmark the combined load before production because host, network, and storage paths are shared.

If choosing G6E

Use QAT W4A16 after a quality gate

QAT was the fastest L40S option: 61 tok/s fixed decode and 252 tok/s at concurrency 16. If quantized-answer quality does not pass, use L40S OPT for BF16 weights with stronger performance than the baseline.

⚠
Quality gate before production selection

The 512-token latency runs frequently ended at the output cap before complete JSON. Performance comparisons are valid, but L40S QAT should be compared with BF16 using natural-EOS responses and scored for schema validity, fact precision/recall, omissions, and hallucinations.
